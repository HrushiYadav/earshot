earshot

A shared-prefix audio decision engine for live microphone input on Apple Silicon.

The idea

[Write this.] Audio LMs are causal; the audio window can be encoded once into the model's prefix state, and then many yes/no and multiple-choice questions can be answered in a single forward pass that forks from it. With 9 questions on a fanless MacBook Air, the batched path is roughly 5× faster than running them one at a time. The output is typed probabilities, not free-form text — there's nothing to parse.

Why a causal model lets you fork

[Write this.] Because Qwen2.5-Omni (and any causal LM) reads each position using only the positions before it, the K/V cache up to a given position is a complete summary of "everything the model would have seen up to here". You can run the audio prefix once, cache that state, and then start a batch of suffix forward passes from that same starting point — the model gives the same answer as if you'd asked each question independently, but you save the audio-encoder + first-N-token forward on each one.

What broke

[Three bugs we hit during Stage 0–3, with the cause and fix each.]

30 s padding in the audio processor

The Qwen2.5-Omni Qwen2_5OmniProcessor defaults to padding="max_length" and pads input_features to 30 s regardless of input length — even if you pass a 3 s clip. Fix: pass audio_kwargs={"max_length": n_samples, "truncation": True} to the processor. For a 3 s clip at 16 kHz that is max_length=48000 and the result is (1, 128, 300) — 100× fewer frames for the audio encoder to attend over.

audios=[audio] vs audio=audio

Passing the audio under the plural key (audios=[audio]) is silently ignored; the model sees no audio and the chat-template placeholders expand to zero <|AUDIO|> tokens. Pass audio=audio (singular) — the processor expands the placeholders from the audio= kwarg.

batch_repeat_interleave(N) returns None

DynamicCache.batch_repeat_interleave(N) in transformers 5.17.0 mutates the cache in place and returns None. Writing expanded_cache = past_kv.batch_repeat_interleave(N) and passing expanded_cache as past_key_values silently forwards None and the suffix forward runs without any audio prefix — the model answers the bare question text with no audio context. Symptom: the batched P(Yes) came back identical for every silence clip because the audio wasn't being seen at all. Fix: just call past_kv.batch_repeat_interleave(N) without assigning the return value, and pass past_kv itself as past_key_values.
