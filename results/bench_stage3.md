# earshot — Stage 3 bench (sequential vs batched)

Generated by `scripts/dev/bench_batch_vs_seq.py` on a single clip
(`clips/calm_1.wav`) with the production question set loaded from
`questions.yaml` (9 model bool questions; `silent` and `main_sound`
excluded &mdash; the former is signal-source, the latter is choice and
needs a different scoring path).

- **Device:** Apple M4 MacBook Air, 16&nbsp;GB
- **Backend:** PyTorch on MPS, `attn_implementation="eager"`
- **Precision:** fp16
- **Clip:** `clips/calm_1.wav`, 5.00&nbsp;s
- **Warm-up:** 3 sequential + 3 batched (untimed)
- **Timed passes per N:** 5, median taken
- **N values:** 1, 4, 8

Raw data: [`bench_stage3.csv`](bench_stage3.csv).

## Results

| N | sequential (s) | batched (s) | speedup |
|--:|---------------:|------------:|--------:|
| 1 | 0.638          | 0.766       | 0.83&times; |
| 4 | 2.659          | 0.882       | 3.01&times; |
| 8 | 5.790          | 1.247       | 4.64&times; |

Batched is faster from N&nbsp;&ge;&nbsp;4 and reaches &times;4.64 at
N=8. At N=1 the prefix overhead makes batched slightly slower. The
production live loop runs N=11 (10 bool + 1 choice), where batched is
expected to keep getting faster (Stage 6's full bench will measure
N&nbsp;&isin;&nbsp;[1, 4, 8, 16, 32] with 30 timed passes after a 2&nbsp;min
warm-up).

## Notes

- These numbers are from one M4 Air, one clip, fp16, eager attention.
  MPS allocator behaviour shifts the absolute timing run-to-run; the
  *speedup* is the stable claim.
- The earlier Session-1 numbers (`N=8: seq=7.751 / bat=1.637 / &times;4.73`)
  used the same script on the same clip with the same model and a
  different MPS allocator state. The newer run is slightly faster on
  both arms because warm-up was longer; the speedup ratio is in the
  same 4.5&ndash;4.8 band.
- **Stage 6 will replace this.** The Stage 3 quick bench is a sanity
  check; Stage 6's `scripts/bench.py` will add N=16, N=32, 30 timed
  passes, and a thermal-throttling pre-warm.
