# earshot — eval_clips results

Generated by `scripts/eval_clips.py` on the production question set
(`questions.yaml`, 10 bool + 1 choice) against the labelled clip set
(`clips/manifest.csv`, 21 clips).

- **Device:** Apple M4 MacBook Air, 16&nbsp;GB
- **Backend:** PyTorch on MPS, `attn_implementation="eager"`
- **Precision:** fp16
- **Clip length:** variable per clip (most 5&nbsp;s; 3&nbsp;s windows are live-only)
- **Per-question thresholds:** from `questions.yaml` (`enter: 0.5`,
  `exit: 0.4`); `silent` uses RMS threshold `0.00505` from
  `SIGNAL_SILENT_RMS_THRESHOLD`
- **Runs:** 1 sequential forward per (clip × question); total runtime
  `231.3 s` (`per-clip 11.0 s`, `per-(clip × Q) 1.00 s`)
- **Always-No baseline** on this set: `0.845` (179 / 210 No cells
  answered correctly by always-No on the bool questions; the model has
  to beat that to be useful)

Raw data: [`eval_clips.csv`](eval_clips.csv).

## main_sound &mdash; choice question breakdown

`main_sound` is the only choice question; options are `[speech, music,
noise, silence]`. The model picks the highest-probability letter token.

| expected option | caught | total |
|-----------------|-------:|------:|
| speech          | 9      | 11    |
| music           | 2      | 2     |
| noise           | 3      | 5     |
| silence         | 1      | 3     |

`main_sound` is the worst-performing question (0.714). The hardest
case is `silence`: on three ambient-silence clips (silence_2,
room_noise_1, alarm_1) the model picked `noise` (twice) or `silence`
(once) instead of `silence` — the tier rule in section 07 of the post
overrides this at the UI level only; the JSONL log captures the full
distribution.

## Yes-case totals (model bools, the headline number)

The "yes_caught" cells above sum to a single number for the model bool
questions (excluding `silent`, which is signal-source):

- Yes cases caught: 11 + 2 + 3 + 2 + 1 + 1 + 2 + 1 + 1 = **24**
- Total Yes cases: 11 + 2 + 4 + 2 + 1 + 1 + 2 + 1 + 1 = **25**
- Catch rate on Yes: **24 / 25 = 0.960**

(Counts above are read directly from the eval output's `yes_caught=N/M`
column. The single miss on a Yes case is `music_speech_2` for
`music` — the model gave `0.385` for a clip with both music and
speech, which is exactly the case the manifest labels "music" as the
dominant sound.)

## Limitations

- **21 clips is small.** Most questions have only 1–4 "Yes" clips in
  the set; the `yes_caught` rate on a single Yes case is a coarse
  measurement.
- **My voice, my room, one recording session.** Inter-speaker and
  inter-room generalisation is not tested.
- **`said_stop` has one Yes clip.** `yes_caught=1/1` is not a strong
  claim of accuracy &mdash; it just means the one clip got it.
- **`music_speech_2`'s ground-truth label of "music"** is the source of
  the only Yes-side miss; the model picked `silence` P=0.32 / `speech`
  P=0.39 / `music` P=0.39, which is genuinely ambiguous audio.
